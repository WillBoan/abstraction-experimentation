Search-space control · mental model

What's possible — the space-shaping levers

Two ways to control what programs the search can express at all: curate the vocabulary, or flip a capability switch the vocabulary can't reach. (Dynamics — budget, cost, strategy — is a separate story, left out here.)

A Summoned by the input vocabulary

Control = curate the bag. Each capability is ON exactly when a primitive whose type signature demands or provides it is present. No switch needed — the type does the summoning.

B Not fully gated by vocabulary → give it a switch

Curating the bag can't cleanly turn these on/off — either invention can re-summon them through the back door, or they answer how, not what. So they deserve their own per-run config.

◆ Primitive co-dependency clusters

One rule generates every cluster: a type is useful only if the bag has both a producer (an on-ramp) and a consumer (an off-ramp) that put it on a typed path from the input Grid back to the output Grid. A type with no path home is an island — dead weight.

The through-line: types summon capabilities (Table A), some capabilities slip past vocabulary and need their own switch (Table B), and the vocabulary only pays off when its types form a connected on-ramp/off-ramp path from input to output (the graph). Curating the bag is necessary but never sufficient.
