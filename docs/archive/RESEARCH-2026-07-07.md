**What moved since 2026-07-06.** No experiment changed the numbers; a **landscape review** did (EXPERIMENTS 2026-07-07). Three shifts: (1) a new Floor axis — **descriptive/parse vs. transformational** — is now the sharpest framing of the perception-poor gap; (2) we located the project precisely against prior art (Ferré/MADIL, Stitch/DreamCoder, CompressARC, the LLM-TTT frontier); (3) the open questions sharpened around one **unoccupied position**.

**Goal [C].** Unchanged. The artifact is the _machinery_ — a solver that forms abstractions, plus the search and **governance** that decide which sub-programs earn a name, when to retire one, how to keep the library searchable. The learned library is _observed, not targeted_; ARC score is a gauge, never the objective.

**The bootstrap cycle [H].** Unchanged. Low floor + weak machinery → solve small-gap tasks → _compress_ solutions into abstractions → abstractions _speed up search_ → machinery bridges a _wider gap_ → repeat. (DreamCoder-shaped.)

**Levers — a factorial design; move one at a time [H].**

- **Floor** (`substrate/`) — the primitive vocabulary. A vector: grain × paradigm × gifted control. Principle: _gift control, withhold domain_ **[C]**.
  - **New framing [H]:** the deepest Floor axis is **transformational vs. descriptive**. Today's substrate is transformational (a `Program` maps `input→output`, cost = node count). The unbuilt half is **descriptive**: a _model that parses a grid into structure and renders it back_ — the perceive/render (intro/elim) pair [ONTOLOGY](../ONTOLOGY.md) flags as "perception-poor, render-poor." Ferré's ARC-MDL/MADIL is a worked existence proof that the descriptive paradigm is viable and human-legible (see _Where we sit_). This is now the **highest-leverage empty region**, above more machinery.
- **Curriculum** (datasets / eval slices) — which tasks, in what order. Still the real-input half of the old "target abstractions."
- **Machinery** (`search/`, `cost.py`, `Library.extended`) — search + compression + governance objective = two-part MDL `DL(sols|lib) + DL(lib)` **[H]**. Build methodology now lives in [MACHINERY-STRATEGY-2026-07-07.md](MACHINERY-STRATEGY-2026-07-07.md).

**Where we sit — prior art [H].** The review placed us. Three families, and one gap none of them occupy.

- **Symbolic MDL, per-task (Ferré: ARC-MDL, MADIL).** Object-centric _descriptive_ models, two-part MDL `L(M) + L(E|M)`, one model that both parses and generates, MDL-guided **refinement** search (greedy → MCTS, _no learned guidance_). OCaml, GPLv3, single CPU, <1 min/task, interpretable. **2% (2022) → 7% (2024) on ARC-1.** Crucially, **fits a fresh model per task — no cross-task library learning.** The closest sibling on _representation + MDL_; silent on _transfer_.
- **Symbolic library learning (DreamCoder → Stitch/babble; LILO, AbstractBeam).** The wake-sleep, abstraction-reuse, library-as-prior lineage — _our_ axis. Stitch is corpus-compression invention 3–4 orders of magnitude faster than DreamCoder's version spaces; LILO = LLM-wake + Stitch; AbstractBeam = bottom-up synthesis + library learning (our exact shape). Neural DreamCoder-for-ARC scored ~4.5%; neurally-guided induction ~5.8% — "fast search still beats smart search."
- **Neural / LLM (CompressARC; the TTT frontier: ARChitects, SOAR, o3).** CompressARC — pure per-puzzle MDL, no pretraining — hits **~20% eval / ~4% ARC-2** and coins "compression leads to understanding": _independent validation of our north star, and its ceiling._ The competitive frontier is LLM test-time training (ARChitects 53.5% ARC-1) and LLM-guided evolutionary synthesis (SOAR) — everything collapses on ARC-2 (o3 76%→~4%).

Read-off **[H]:** (a) pure symbolic/MDL ARC solving is a single-digit-to-~20% game _as a score_ — which is fine, score is not the deliverable; (b) we are **deliberately off the competitive (LLM-TTT) frontier**, and should stay off it — that path trades away the determinism and inspectability that make findings mean anything; (c) the **unoccupied position** is _Ferré-style descriptive representation × cross-task library learning_ — a descriptive model whose recurring parts are compressed into a transferable library. Neither Ferré (no library) nor DreamCoder/Stitch (transformational programs, not descriptive parses) sits there.

**Metrics.** Unchanged in structure (experiment ⊃ run ⊃ task ⊃ program; optimize compression, **report** transfer, **diagnose** with the compression↔transfer correlation). One refinement **[O]:** Ferré's `L(E|M)` residual (the cost of _describing the data given the model_, in real bits) is a more complete objective than our node-count `ProgramSize` — a concrete shape for the long-open "real DL units vs. node-count."

**Disciplines [C]:**

- Targets → observables: never optimize toward a _named_ abstraction.
- Optimize compression, **report** transfer, **diagnose** the correlation (it tests the MDL premise). Metric-that-drives ≠ metric-that-grades.
- A negative at a low floor indicts _Floor × Machinery_, never the floor alone.
- Preserve regression locks; keep determinism; `make check` green.
- **New [H]:** _adopt don't rebuild; maps predict, tasks adjudicate_ — the build methodology (see [MACHINERY-STRATEGY-2026-07-07.md](MACHINERY-STRATEGY-2026-07-07.md)).

**Open [O]:**

- **The unoccupied position:** descriptive (perceive/render) representation × cross-task library learning — is it real, and does it climb?
- **Does compression predict transfer?** — CompressARC says compression buys real ARC understanding _with a ceiling_; our own correlation is still unmeasured on real tasks.
- Descriptive vs. transformational floor — which paradigm the loop should compress over.
- `L(E|M)` residual (real bits) vs. node-count cost.
- AST variable binding — now framed concretely as a **De Bruijn / Stitch-compatible** lambda-index (F0 keystone).
- Curriculum construction; gift vs. invent recursion; pure vs. stateful floor.

**Next probe [O].** Two moves, in order: (1) the F0 substrate keystone — the De Bruijn lambda-index, built Stitch-compatibly (unlocks the low-floor thesis _and_ cheap future Stitch adoption); (2) **shift the workload from synthetic microworlds toward real ARC tasks**, so reality — not the maps — writes the build queue. The maps predict; the tasks adjudicate.
