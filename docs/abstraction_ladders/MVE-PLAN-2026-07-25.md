## Strategy

**MVE-first, then expand.** Build the smallest set that runs end-to-end (certificate + climbs + raw arms + report) and yields the headline measurements; every further axis is an _expansion of a running set_, not a prerequisite. The uniform grid (~tasks x cohorts x sub-cohorts x members) is a coverage aspiration for the full set, not a requirement on the MVE — sampling the space matters, forcing symmetry does not.

## The corrected cost model

What the audit + alignment session established about what actually drives MVE cost. **Cheap or fine (not constraints):**

- **Large `d_raw`.** The task screen _requires_ raw-intractability, and RQ1 is measured-or-bounded (AL-PLAN-2026-07-23 decision 1): a censored raw arm is a proven `>= K x` bound, not a failure, and its compute is guarded at `K x laddered` regardless of `d_raw`. There is **no target `d_raw` band**; the only hard lower bound is "not raw-solvable from the floor" — already a lint (`raw-intractable`).
- **Many rungs.** Structurally fine; the cost that scales with rung count is demo authoring (below), not science.
- **Custom floor primitives.** Admissible when a task earns them. The promotion loop exists and worked (item 15/16); cross-task comparisons are unlicensed anyway (raw only cancels within a cohort), so a bespoke floor corrupts no comparison the program actually makes. It is per-task authoring cost, bounded — a line item, not a disqualifier.
- **Raw arms.** Bounded compute via the K-guard; one per cohort; not a shaping constraint.

**The real cost centers:**

1. **Demo plans per rung** — the dominant, linear-in-rungs cost, and exactly what blocks v5-core today: the `free-param-varies` class (every demo feeds a param the same value-pattern, so sleep would specialize instead of minting at intended arity — the S-B law). Tooling covers the _check_ side (lint/probe, seconds) but the _select_ side is manual.
2. **Unfold blowup on shared DAGs** — a mechanical defect, not a design limit: `substitute_params` duplicates subtrees, so unfolding a many-rung DAG with high fan-out can go exponential in term size at modest `d_raw` (v5-full's non-termination). Gates only tall shared-DAG ladders; fix deferred with them.
3. **Per-task fixed cost** — a verified solution term over the substrate + a pool of task-realizable grids + (sometimes) new primitives with ground-truth validation.

## Decisions of record (2026-07-25)

1. **Screen on `arc1-train` only.** `arc1-eval` stays reserved: every task we design ladders/primitives around is spent for uncontaminated solver benchmarking. cfb2ce5a (in eval) is already spent — one task, bounded; no reason to spend more.
2. **The regression locks are the too-easy filter, for free.** `tests/program_search/execution/test_locks.py` pins which arc1-train tasks the presets solve at cheap budgets; that solved set is precomputed Family-B screening. Candidates come from the unsolved remainder.
3. **cfb2ce5a stays in the set but is not the anchor.** It is one task — the hard end of the difficulty spread — not the pipeline-proving critical path.
4. **The MVE cuts** (each an expansion of a running set, not a prerequisite): cfb2ce5a Cohort A (the v1/v3 high-floor line — v1 fails `proper-composition` on 8 rungs and both need full demo authoring; the floor-power ablation returns in wave 2) · v5-full and the unfold-blowup fix · in-file floor definitions · the demo-pool selector · second sub-cohorts per cohort.
5. **Deferred-with-trigger items** are recorded below, not silently dropped.

## The MVE

**Composition (~8-10 ladders, 3 real tasks):**

| Task | Cohort | Sub-cohorts | Members |
| --- | --- | --- | --- |
| cfb2ce5a | B — partially-lowered floor (v5-core, demos fixed) | 1 spine | 2-3 (cut-sets) |
| Task B (new, train) | 1 | 1 spine | 2-3 (cut-sets) |
| Task C (new, train) | 1 | 1 spine | 2-3 (cut-sets) |

**Steps, in order:**

1. **Task screen** — from arc1-train's unsolved-by-preset remainder, find 2 tasks where a solution term is hand-authorable over the current substrate (~117 primitives; new primitives allowed where a task earns them), verified against ground truth. Pick for a spread: one straightforward, one meatier.
2. **cfb2ce5a Cohort B** — fix v5-core's demo plans by hand (the 15 errors are one class: dead `rot180` rung + discriminating grids), then lint → probe → taskgen.
3. **One spine + 2-3 cut-set members per task** — spine-as-generator per LADDER-SET-DESIGN; coarser members derived from cut-sets; demos re-derived per member (S-B: the demo value-patterns ARE the mint's spec).
4. **Run the grid** — per member: certificate (per-rung verdict profile, per CERTIFICATE-PROFILE) + both climbs (`full` + `skip-solved`, watching recovery/junk/cascade) + one raw arm per cohort (K=10). EXPERIMENTS.md entry per batch; one written report.

**Gate layering per ladder (unchanged):** `lint-ladder` → `probe-ladder` → `diff-ladder` (membership/equivalence for derived members) → `taskgen` commit → `run-ladder` + raw arm.

**MVE exit criteria** (relaxing the 07-24 plan's Phase-1 criteria, deliberately): all members through the staged pipeline; **>= 8 profiled ladders across 3 real tasks**; granularity curves (cost vs cut density) for >= 2 sub-cohorts; a measured-or-bounded RQ1 per cohort; a written report. The cohort ablation (two floors of one task) moves to wave 2. Per the 07-24 plan: broad certification _failure_ (Family-B on real tasks) is a result, not a failure of the MVE.

## Design disciplines (carried forward, binding)

- **Constant policy per floor kind**: `finite-enumerate-scalars` on addressing-tier floors (the Phase-0 probe's >20x finding — coordinates come from perception, small direction literals from scalars); off/minimal wherever a perceiver route covers everything. Phase-1 cohorts stay clean depth experiments (BREADTH-AXIS).
- **Natural mixed depths** — do not uniformize to all-d2; the certificate is a per-rung verdict profile, not a sandwich gate (CERTIFICATE-PROFILE; `double-jump-intractable` is warn-severity as of 2026-07-25's working tree).
- **Budgets derived from each member's validity window** (default: window minimum; global `depth_limit` = max rung depth until per-rung budgets land in Phase 2).
- **Parameterization declared per sub-cohort**, documented as the bind-early/bind-late choice it is.
- **Everything gated before it runs**; no ladder authored without its demo plan checked (`free-params-covary`, `free-param-varies`, probe).

## Risks

- **The screen may not find 2 cheaply-expressible tasks fast.** Mitigation: new primitives are admissible (decision above), and the candidate pool is large (arc1-train's unsolved remainder). Time-box the screen; a spread of 1 new task + cfb2ce5a still exercises the full pipeline.
- **The v5-core demo fix may be slower than expected** — that is precisely the selector's trigger firing; build it then, not before.
- **Demo authorship cost remains unquantified** (07-24 risk, still open) — the MVE's steps 2-3 are its first measurement; note the actual time spent.
